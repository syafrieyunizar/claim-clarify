Claim Clarify

by Syafrie Yunizar

Kebijakan Privasi

Terakhir diperbarui: 12 Agustus 2026

Claim Clarify membantu pengguna menyusun draf jawaban pending klaim BPJS dari dokumen yang dipilih pengguna. Dokumen diproses dan disensor secara lokal terlebih dahulu. Hanya teks yang telah melalui penyensoran otomatis yang dikirim ke layanan AI ketika pengguna meminta analisis.

1. Ruang lingkup

Kebijakan ini berlaku untuk ekstensi Chrome Claim Clarify. Dengan menggunakan fitur pemrosesan dokumen atau AI, pengguna memahami bahwa data yang dipilih akan ditangani sebagaimana dijelaskan di halaman ini.

2. Data yang ditangani

  • Isi dokumen dan informasi kesehatan: teks dari PDF yang diunggah, tautan PDF, atau PDF pada tab aktif yang dipilih pengguna, termasuk diagnosis, tindakan, hasil pemeriksaan, dan informasi klinis lain.
  • Data identitas yang mungkin terdapat pada dokumen: antara lain nama pasien, NIK, nomor SEP, nomor rekam medis, nomor kartu, tanggal lahir, alamat, nomor telepon, serta identitas fasilitas kesehatan.
  • Masukan dan hasil kerja: alasan pending, alasan tambahan pengguna, jawaban yang dihasilkan, template, knowledge, draf kasus, dan riwayat kasus.
  • Data autentikasi dan konfigurasi: username, password, token sesi akses admin, endpoint, model AI, dan API key pribadi yang dimasukkan pengguna.
  • Metadata pemakaian mode admin: username, provider, model, status keberhasilan, durasi permintaan, serta jumlah karakter input dan output. Log ini tidak menyimpan isi prompt atau jawaban AI.

3. Pemrosesan dan penyensoran lokal

Ekstraksi teks PDF dan penyensoran identitas dilakukan pada perangkat pengguna sebelum permintaan AI dibuat. Claim Clarify dirancang untuk mengganti pola identitas yang dikenali, termasuk nama pasien, NIK, nomor SEP, nomor rekam medis, nomor kartu, tanggal lahir, alamat, nomor telepon, dan nama fasilitas kesehatan.

Penyensoran otomatis tidak dapat dijamin mengenali setiap format atau kesalahan penulisan. Pengguna tetap bertanggung jawab meninjau dokumen dan hasil penyensoran sebelum menggunakan layanan AI. Informasi klinis yang telah dideidentifikasi tetap dipakai karena diperlukan untuk menghasilkan analisis klaim.

4. Penyimpanan lokal

Pengaturan, API key pribadi, template lokal, knowledge lokal, draf, hasil, dan riwayat kasus disimpan melalui chrome.storage.local pada perangkat pengguna. Data tersebut tidak disinkronkan melalui chrome.storage.sync. Data dapat dihapus dari antarmuka ekstensi, dengan menghapus data extension melalui Chrome, atau dengan menghapus extension.

5. Data yang dikirim dan tujuannya

  • Provider AI yang dipilih pengguna: teks klinis yang telah melalui penyensoran, alasan pending, instruksi, knowledge relevan, dan jawaban sebelumnya dikirim hanya ketika pengguna meminta pembuatan, revisi, atau penilaian jawaban.
  • Supabase Claim Clarify: digunakan untuk autentikasi akun admin, token sesi, library knowledge/template bersama, pengajuan knowledge/template untuk moderasi, metadata pemakaian, dan relay permintaan AI dalam mode API admin.
  • Library bersama: knowledge atau template lokal hanya dikirim untuk moderasi setelah tindakan eksplisit pengguna. Konten yang disetujui pemilik dapat dibagikan kepada akun Claim Clarify lain.

Claim Clarify tidak menjual data pengguna, tidak menggunakan data untuk periklanan, tidak menentukan kelayakan kredit, dan tidak menggunakan data untuk tujuan di luar penyusunan serta evaluasi jawaban pending klaim.

6. Pihak penerima data

Data dapat diproses oleh Supabase dan oleh provider AI yang dikonfigurasi untuk menyediakan fungsi yang diminta pengguna. Pada mode API pribadi, API key dikirim hanya kepada endpoint AI yang dipilih pengguna. Pada mode admin, API key pusat tidak disimpan di extension dan permintaan diteruskan melalui Supabase Edge Function ke provider AI aktif. Kebijakan dan masa simpan provider tersebut dapat berlaku terhadap data yang diterimanya.

7. Izin Chrome

  • sidePanel: menampilkan antarmuka Claim Clarify di sisi browser.
  • storage: menyimpan pengaturan dan data kerja secara lokal.
  • activeTab dan tabs: mengenali serta membaca PDF pada tab aktif, atau mengoordinasikan halaman e-Klaim selama otomatisasi yang dimulai pengguna.
  • scripting: mengisi SEP dan menekan kontrol Re-grouping hanya pada tab e-Klaim aktif setelah tindakan eksplisit pengguna.
  • file:///*: membaca PDF lokal yang dipilih pada tab aktif setelah pengguna mengaktifkan izin akses file.
  • Izin host opsional: mengunduh PDF dari tautan yang dimasukkan pengguna, menghubungi endpoint AI yang dipilih pengguna, atau menjalankan Re-grouping pada origin e-Klaim aktif.

Claim Clarify tidak mengumpulkan riwayat penelusuran dan tidak memantau klik, posisi mouse, ketikan, atau aktivitas browser pengguna.

8. Keamanan

Claim Clarify membatasi akses data pada fitur yang diminta pengguna, tidak mencatat API key atau isi rekam medis ke console, dan menggunakan koneksi HTTPS untuk layanan Supabase serta endpoint bawaan. Pengguna harus memilih endpoint AI yang aman dan tepercaya.

9. Retensi dan penghapusan

Data lokal disimpan sampai pengguna menghapusnya. Pengajuan knowledge/template dan data akun admin dapat tersimpan di Supabase selama diperlukan untuk menyediakan library dan akses layanan. Permintaan penghapusan data layanan dapat diajukan melalui kontak di bawah.

10. Limited Use

Penggunaan informasi yang diterima melalui API Chrome mematuhi Chrome Web Store User Data Policy, termasuk persyaratan Limited Use. Data hanya digunakan untuk menyediakan atau meningkatkan fungsi tunggal Claim Clarify sebagaimana dijelaskan dalam kebijakan ini.

11. Perubahan kebijakan

Kebijakan ini dapat diperbarui apabila fitur atau praktik pengelolaan data berubah. Tanggal pembaruan akan dicantumkan di bagian atas halaman.

12. Kontak
